# recovery-plane

Companion lab for **Article 5 — When the Network Fails, Your Control Plane Must
Survive**.

```bash
make verify
```

27 tests, no cloud project, no credentials, no network.

## What this proves

On 4 October 2021, Meta's backbone went down. Their report contains the
sentence this module exists for:

> "it was not possible to access our data centers through our normal means
> because their networks were down, and second, the total loss of DNS broke
> many of the internal tools we'd normally use to investigate and resolve
> outages like this"

The tools needed to fix the outage depended on the thing that was broken.

Nobody designs that. It is a property of a graph nobody drew. So this module
draws it and checks it.

## The validator

Declare components with their failure domains and dependencies, declare
recovery steps with the domain each repairs, and the validator walks the
transitive closure looking for steps that depend on the domain they are meant
to fix.

Against the same fictional estate:

| Step set | Findings | Safe steps |
|---|---:|---:|
| Undesigned | 13 | 0 |
| Designed against the graph | 0 | 3 |

The undesigned `restore-dns` step fails because it reaches its bastion through
IAP, and IAP needs DNS. That is the Meta shape, reproduced in a graph.

## Independence is derived, never declared

The first implementation had an `independent: true` flag. Test `T6` killed it
within minutes: the flag was an assertion that silently excluded a component's
whole dependency subtree from validation. Mark the bastion independent and the
validator stops looking, which is the failure this tool exists to catch,
reintroduced as a feature.

A component is now an **anchor** when nothing in its transitive closure belongs
to any failure domain — computed, not claimed. `N2` shows two differently-named
tools, both resting on `corp-dns`, and neither is an anchor however it is named.

## Break-glass

Modelled on Privileged Access Manager's shape: entitlements, time-bounded
grants, automatic revocation, required justification, dual control, and no
self-approval even when the same person appears on both lists.

`T20` is the one worth reading. The recovery path is not blocked from daily use
— it is made so visible that daily use is obvious: bounded grants mean
continuous access requires continuous, individually approved, individually
logged requests.

## Why the audit log is the foundation

Because it is the one dependency the operator cannot remove:

> "Admin Activity audit logs are always written; you can't configure, exclude,
> or disable them."

Most controls protect against an outsider. That one holds against the person
using the recovery path, which is the threat model that matters here.


## What this lab is not

It provisions nothing and calls no Google Cloud API. It models the *structure*
of a recovery plane — which dependencies exist and which survive — and that
structure is the part that was wrong in 2021.

No timing claims are made anywhere. Meta's report gives no restoration
timeline, and no recovery-path SLA is published by anyone.
