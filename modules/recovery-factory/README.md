# recovery-factory

Companion lab for **Article 6 — A Backup Is Not a Recovery Plan**.

```bash
make verify
```

25 tests, no cloud project, no credentials, no network.

## What this proves

GitLab, January 2017. Five protection mechanisms. The one that mattered had
run successfully:

> "The backup procedure was using `pg_dump` 9.2, while our database is running
> PostgreSQL 9.6."

The job executed. It exited. It produced a file. The file was useless, the
failure email was discarded, and:

> "Why was the backup procedure not tested on a regular basis? - Because there
> was no ownership, as a result nobody was responsible for testing this
> procedure."

**A completed backup job is not evidence of recoverability.** It is evidence
that a process exited zero. This module makes that distinction executable.

## The measured result

From `results/report.md`. Simulated results; RTO and RPO are measured inside
the model and are not vendor figures or targets.

| Scenario | Outcome | Steps | RTO | RPO | Failed invariants |
|---|---|---:|---:|---:|---:|
| Healthy restore | `RESTORED_AND_VALIDATED` | 7/7 | 7 min | 4.0 h | 0 |
| **Backup job succeeded, output unusable** | `BLOCKED_UNREADABLE_ARTIFACT` | 4/7 | 4 min | 4.0 h | 0 |
| Encryption key unavailable | `BLOCKED_MISSING_KEY` | 1/7 | 1 min | 4.0 h | 0 |
| Manifest omits a dependency | `BLOCKED_MISSING_DEPENDENCY` | 0/7 | 0 min | 4.0 h | 0 |
| **Restore completes, invariants fail** | `RESTORED_BUT_INVALID` | **7/7** | 7 min | 4.0 h | **3** |
| After a hostile delete attempt | `RESTORED_AND_VALIDATED` | 7/7 | 7 min | 4.0 h | 0 |

Read rows two and five together. Row two is a job that worked and produced
nothing. Row five is a restore that completed **every step** and produced a
broken ledger. Neither is detectable by asking whether the process succeeded.

## Protection against the operator

| Action by a fully privileged identity | Result |
|---|---|
| Delete the locked artifact | `RETENTION_POLICY_NOT_MET` |
| Shorten its retention | refused — locked retention policy cannot be reduced |
| Extend its retention | permitted |

Protection is a ratchet. The safe operation is always available; the unsafe one
never is. `N3` covers the subtler attack — shorten retention first, then delete
legitimately — which a locked policy also refuses.

## Why the invariants matter more than the steps

`N4` is the test to read. Two restores, one from a clean artifact and one from
an artifact missing a single credit posting:

- identical completed-step lists, `deepEqual` passes
- 7 of 7 steps in both
- one is `RESTORED_AND_VALIDATED`, the other `RESTORED_BUT_INVALID`

A row count would have seen one fewer row and called it a smaller dataset.

## The manifest

`manifests/recovery-manifest.json` is the machine-readable artifact:

```text
project → key ──┐
project → storage ──┼→ data → reference → validate
project → schema ──┘
```

Order is part of the contract. Data restored before its key is ciphertext;
before its schema, it is corruption. `T9` asserts the ordering, `T14` refuses
cycles, and `T13` treats an undeclared dependency as a blocking finding rather
than a silent skip.

## What this lab is not

It creates no cloud resources — no bucket, no lock, no KMS key, no Spanner
instance. It models the *structure* of a protected restore: ordering,
immutability, key dependency, validation, evidence.

It quotes no vendor RTO or RPO. Both are measured in the model and labelled
`Simulated result`. Presenting an untested RTO as achieved is exactly what the
article argues against.

Backup and DR Service is deliberately absent. Its documentation was not read
during this run, so the module does not model it rather than guessing.
