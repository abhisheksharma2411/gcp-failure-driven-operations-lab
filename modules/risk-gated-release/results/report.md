# Release-risk results

Generated by `make report`. Deterministic; no cloud project, no network.

## Required gates by change type and blast radius

| Change type | single-instance | single-region | global |

Gate counts, not names, so the shape is visible. Full sets are in
`results/release-risk-manifest.json`. Every type at global radius carries the
same seven core gates; schema, IAM and edge-policy add a compatibility check.

## Exposure under failure

| Scenario | Outcome | Reached phase | Max traffic exposed |
|---|---|---|---:|
| gated, healthy | COMPLETED | stable | 100% |
| gated, error-rate regression at 25% | HALTED | canary-25 | 25% |
| gated, business check fails at 25% | HALTED | canary-25 | 25% |
| manifest blocks the ungated change | BLOCKED_AT_GATE | none | 0% |
| no manifest at all, broken change | HALTED | stable | 100% |

Row three is the manifest doing its job: the change never reaches traffic at all.
Row four is the 2019 shape, and it needs the gate to be ABSENT rather than failed --
running an ungated change through the gated path just gets it blocked, which is the
manifest working. Without any gate, the regression is detected after everything is
already exposed.
